# 架构

[English](architecture.md)

协调器记录跨 Owner 工作流及明确批准。Runtime 负责进程和结果发布；Research 负责准入、研究结论、独立审查和晋升；数据与报告 Owner 保留各自契约。

调用关系为 CLI/TUI → 协调器 → 各 Owner CLI，状态和审计保存在 SQLite。回环地址 API/GUI 只读取经过字段白名单处理的视图，提供比较、历史、影响和轨迹评分。GitHub Pages 使用独立的合成浏览器数据。

调度先持久化意图，再执行外部操作。响应丢失时按原 Owner 身份核对，不盲目重提。计算成功、输入完整性、历史 PIT、执行语义和研究结论分别记录；协调器的晋升状态始终未知。

Codex 生命周期和工具权限由 Research Owner 管理。v1 无工具，v2 显式绑定四类只读 MCP 工具及文件身份；协调器也能只读关联已有回执，无需调用模型。Campaign 只协调已批准的既有提案，不引入 LLM 路由或自治专家团。

Owner 证据可声明范围与有效期。新步骤要求的资料、策略、研究范围指纹、历史时点和样本覆盖必须匹配。审查有效期使用当前时间，与市场历史时点分离；过期阻止新准入，不改写已完成研究。旧的无范围工作流仍可读取，不自动获得范围认证。

历史快照和评测报告是可替换的展示投影，不是第二套研究权威库。历史只导入固定摘要的明确 Owner 导出，工况失败不等于经济否定。比较展示工程身份与观测用量，不声称未导出的金融指标或因果。影响预览读取一致的 SQLite 快照，不执行任务。参考轨迹评分只检验固定评测器，不代表模型能力。

GUI、TUI 与 API 共用字段受控视图。API 只绑定回环地址，可要求私有 Bearer 令牌，拒绝 HTTP 修改；查询不调用 Owner。中英文文案与机器契约分离。安装后的离线演示使用公开协议 peer 和外部输出目录，不依赖私有包或模型。

系统为单机、每数据库一个调度器，运行可信 CLI，不提供操作系统级沙箱；部署须另行配置进程身份与隔离。恢复、本地通知核对、迁移预检不切换生产调度、不外发消息。独立只读工作台上线也不代表生产任务已迁移。

QuantStudio 与 DeepSeek Super-agent 仅提供能力发现、持久任务分离方面的架构参考，本仓未复制其源码。详见 [Owner 适配](owner-adapters.md)、[证据适用性](evidence-applicability.zh-CN.md)、[研究洞察](insights.zh-CN.md)和[研究集成](research-closure.zh-CN.md)。
