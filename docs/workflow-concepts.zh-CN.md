# 如何阅读研究工作台

[English](workflow-concepts.md)

先看选中流程的执行状态、研究验证状态和已有的下一步建议。点击“查看步骤证据与恢复建议”定位相关步骤；这个操作只查看记录，不会批准、重跑或取消任务。只有记录中明确缺失的证据才会显示为缺失，没有记录的字段保持未知。

| 界面名称 | 用途 | 权限边界 |
| --- | --- | --- |
| 负责系统 | 说明数据、执行、研究审查和报告分别归哪个项目负责 | Runtime 确认执行结果，Research 判断研究准入和结论；协调器不覆盖它们的判断 |
| 能力库 | 列出可复用任务、输入输出契约和准确版本 | 登记不代表已安装、启用或获准执行，能力本身不负责调度 |
| 流程时间线 | 展示计划、批准、任务分配和状态变化 | 事件是流程记录，不是经济有效性证明；程序详细输出仍属于运行日志 |

负责系统是项目或服务，不一定是某个人。执行身份、代码版本和哈希是另外的技术事实。界面只根据已知适配器类型映射负责系统，未知类型不会猜测。已知事件用自然语言说明，未知事件用中性说明并保留可展开的原始代码。API 和持久化数据中的操作代码保持稳定，界面建议不会授予新权限。

[金融结果声明](economic-results.zh-CN.md)和[只读影子观测](shadow-observations.zh-CN.md)各有独立契约。计算成功、文件摘要一致、观测窗口足够，分别证明不同事实；任何一项单独都不能证明研究结论有效或授权策略晋升。
