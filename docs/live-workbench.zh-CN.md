# 实时研究工作台

[English](live-workbench.md)

本地 GUI 与 TUI 读取同一个协调数据库，展示流程依赖、执行记录、证据和恢复建议。[公开演示](https://runchengxie.github.io/quant-task-orchestrator/)仅使用虚构数据。

```sh
quant-task --database "$TASK_DATABASE" serve-api --host 127.0.0.1 --port 8787
```

打开 `http://127.0.0.1:8787/`。页面每五秒查询一次，支持分页、筛选和中英文切换，时间明确使用 UTC。语言选择在浏览器允许时保存。断线与空数据库分别提示；最后一次观测不代表负责方当前状态。刷新和选择步骤只查询数据，网页不提供批准、取消、重试或模型启动。

## 日常查看

先查看“需要关注”“正在运行”或“执行已完成”。点击卡片筛选流程，再次点击清除筛选。卡片只统计已加载流程；页面同时显示已加载数量和总数。“运行指标”中的计量来自整个数据库。

选中流程后，先查看执行状态和研究验证状态，再查看已有阻塞代码及下一步建议。建议不构成执行授权。依赖图辅助定位步骤，下方继续展示证据。流程哈希、权限、运行及 Agent 用量、事件记录通过折叠面板查看。同一流程刷新时保留展开状态，切换流程时重置。

公开演示提供计算完成、证据不足和执行失败案例，所有模拟操作仅影响浏览器内的虚构状态。

## 证据和恢复

每个步骤分别展示输入完整性、历史 PIT、执行语义、独立审查、经济结论和晋升六个维度。数据发布元数据检查成功，不保证内容完整性或历史 PIT；报告载荷通过校验，也不保证其结论真实或已经交付。原生会话完成不代表研究验收。协调器中的晋升证据保持未知，`promotion_authorized=false`。

恢复建议使用稳定代码。提交状态不明时必须核对原始键和负责方；输入变化要求恢复已批准绑定。执行前阻塞不会自动接管其他任务，研究取消仍需负责方或操作员交接，新执行仍需明确范围及批准。

## 计量和部署

等待、运行、阻塞和未知状态的时长表示协调器观测到的占用时间，不是 CPU 时间。调用次数、协议失败和命令耗时由协调器计量；人工操作次数仅覆盖已记录的批准和取消请求。缺少负责方用量时，模型费用及 CPU 计量保持 `null`。旧数据库可能缺少计量覆盖，重复轮询不会虚构状态变化。

安装包包含静态页面，不依赖源码检出。服务仅绑定 IPv4 回环地址，拒绝非本地 Host/Origin，可配置私有 bearer token；它不提供远程身份系统。远程私有访问需要单独设计部署方案，不应直接公开本地 API。

## 查询接口

- `GET /v1/workflows?limit=100&offset=0`：流程与分页，每页最多 1,000 条。
- `GET /v1/workflows/{id}`：流程、证据、恢复和计量。
- `GET /v1/workflows/{id}/events?tail=100`：最近事件，最多 500 条。
- `GET /v1/workflows/{id}/events?after=SEQUENCE`：按序号分页。
- `GET /v1/metrics`：整个数据库的计量，不受流程列表分页影响。

只读接口打开现有数据库，不执行迁移或调用负责方。可写协调操作会添加辅助表，旧记录仍可读取；最终状态和校验后的观测在同一事务中提交。升级保留状态前应通过 SQLite backup API 备份。
