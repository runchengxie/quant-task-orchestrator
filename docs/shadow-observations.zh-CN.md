# 只读影子观察

[English](shadow-observations.md)

影子运行成功，只能说明记录的那个时点通过了就绪检查。几分钟内连续运行多次，不能证明日常运行稳定。应在有意义的时间跨度内，持续观察同一份已批准配置，再作运维判断。影子证据不授予研究晋级权限，也不授权修改生产调度。

`quant_task_orchestrator.shadow_history` 中的
`summarize_shadows(root, expected_config_sha256, *, limit=500)` 只读取现有
`assessment.json`，返回 `quant.data_shadow_history.v1`。必须提供已批准配置的精确小写
SHA-256 摘要。根目录只能包含以 UUID 十六进制字符串命名的直接运行子目录；其他文件应放在别处。函数不会执行适配器、读取工作流数据库或沿原始数据路径取数，不安装调度器或通知传输，也不修改任何文件。

汇总记录独立运行 ID、各状态数量、失败次数、其他配置摘要的记录数量、无效记录、未知时间戳，以及记录中提供的实测耗时。其他配置有独立状态统计，不能计入指定配置的观察窗口。输出不包含私有路径或原始步骤内容。根目录缺失、不安全，或记录损坏、不可读，都会明确报告错误；函数参数无效则抛出 `ValueError`。

观察时间只取自本地评估记录中带时区的 `observed_at`。旧记录缺少时间戳时保持未知，不从目录名或文件修改时间推断。未来时间戳无效。可选的 `duration_seconds` 必须是有限、非负且不超过 31 天的实测耗时；未测量就不补值。本地记录属于生产者提供的证据，并不能以密码学方式证明运行真实发生或时钟准确。

最低观察窗口要求：至少七次独立成功运行、覆盖至少七个不同的 UTC 日期，且首尾相隔至少完整七天。任何错误、其他配置、未知时间戳或非成功状态，都会使窗口判定为不足。这只是最低监测门槛，不能保证持续可用：检查成功的时点不能覆盖运行之间的空白。即使窗口足够，`qualified_research_ready` 和 `promotion_authorized` 仍为 false。仍需按预期运行频率，单独评估失败原因、时间分布、源数据新鲜度和覆盖要求。

默认最多枚举 500 个条目，可设为 1 至 1,000。每份评估记录最多 1 MiB。发现额外条目会明确标记截断和无效，部分结果不能通过窗口门槛。较大的历史目录应通过明确的保留流程整理，而不是无限提高上限。路径组件或记录中的符号链接、损坏的 JSON、重复对象键、非有限数值及不安全的运行标识符都会被拒绝。

## 命令和持续观测

```sh
quant-task shadow-history --root /absolute/external/shadow-runs \
  --expected-config-sha256 APPROVED_CONFIG_SHA256
```

`shadow-check` 新增 UTC `observed_at` 和单调时钟计量的 `duration_seconds`。配置校验后，绑定或执行失败会保留为失败观测，使用不含私有信息的 `failure_phase`；无效配置仍在创建输出前拒绝。失败观测也可以是正常命令响应，因此必须检查 `status`，不能将退出码零当作数据就绪。崩溃或中断留下的不完整目录会使历史汇总无效。

持续观测应使用稳定安装版本、明确批准的配置 pin 和独立的数据输出目录。可准备用户服务及 timer 供审查，不应引用临时 worktree 或替换原有权威调度。配置 pin 改变后建立新观测组；保留失败，并区分源数据过期与命令失败。本轮只运行有限人工验收，**没有安装或启用 timer**；持续调度和生产迁移仍是单独的运行决策，通知继续留在本地 outbox。
