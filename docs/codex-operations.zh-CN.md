# Codex 与运维增量

[English](codex-operations.md)

有预算的 Agent 任务通过 Research Owner 的 `strategy_app.codex_task` 接口运行，协调器不直接执行模型命令。工作流固定动作、恢复时的原会话与前一份回执、执行文件与提示词摘要，以及累计轮数和时间预算。轮询不会自动恢复任务。Owner 失联需要人工核对；未知用量保留为未知。Token 上限用于后续准入，不是运行中的硬上限，也不是费用上限。

首版仅支持 Linux 和无工具调用，关闭 shell、网络搜索、MCP 和其他 Agent。这能验证生命周期，尚不能自主完成研究计算。接入研究工具需要另行明确契约。取消只作用于 Codex 当前轮次，不会取消独立的 Runtime 任务。公开视图只投影允许的计数与标识，不包含提示词或私有路径。

真实验收使用 Codex CLI 0.167.0，控制在两个会话、三次准入调用和十分钟内。首次尝试因过期配置项失败并终止，随后已移除该项。一个轮次正常完成并返回 Token 计数；同一会话的第二轮成功准入，在 CLI 启动前取消。“恢复后完整运行一轮”仍未验证。此次验收不产生金融研究结论。

原始观测校验由数据 Owner 核对预期根清单、封存的子清单和文件内容。内容完整不代表历史时点可用，也不能让尚未生成研究数据的流程自动通过准入。

[运维命令](operations-next.md)提供持久事件收件箱、本地通知 outbox、固定版本的 Skill 文本安装、发布包暂存、备份和健康检查。通知仅保留在本地；暂存不代表已经安装或激活服务。生产定时任务切换和外部通知渠道仍需部署实现。

私有本地访问可使用 `serve-api --token-file "$GUI_TOKEN_FILE"`，令牌文件须为仅当前用户可读写的普通文件，内容为 32–256 个 URL 安全字符。GUI 仅在内存保留令牌，读取后清空密码框，刷新或断开即丢弃。API 要求 Bearer 请求头，不接受查询参数中的令牌。服务仅绑定回环地址，HTTP 修改操作保持关闭。GitHub Pages 继续只展示合成数据，不包含凭证或实时 API。

## 本轮验证

协调器测试共 91 项：89 项通过，2 项可选报告 Owner 检查未配置。已启用真实安装的 Go Runtime 提交与恢复、数据 Owner 契约和历史原生会话检查，输入与数据库均隔离。另行通过了原始观测和真实 Codex 回执的适配器核对，未追加模型调用。Ruff、编译与前端语法检查通过。浏览器验收覆盖 SQLite 轮询、分页、中英文界面、令牌仅保留在内存，以及退出后延迟响应不得恢复私有内容。

数据 provider 已通过 [PR #183](https://github.com/runchengxie/quant-market-data-platform/pull/183) 合并，merge 为 `e576ef761665145b4a9aa3811da028904d320587`，完整门禁 2,280 项通过、1 项跳过。Research 生命周期 provider 已通过 [PR #651](https://github.com/runchengxie/quant-research/pull/651) 合并，merge 为 `dad0511564c204591edf259f1fde5afa124eadc7`，42 项相关测试通过。独立复核补充了过期准入和退出竞态的回归检查。

仍需推进：具备研究能力的 Agent 工具、恢复后完整运行一轮的真实验收、归一化 PIT 数据与合格研究验收、外部通知渠道，以及明确的生产调度切换。本轮工具提供暂存与检查能力，不代表这些生产流程已经采用新系统。

认证回归做了双向核对：移除响应版本检查时，延迟响应测试失败；恢复后通过。
