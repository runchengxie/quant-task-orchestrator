# Research workflow closure

Advance the remaining owner integrations while keeping computation, research
qualification and production adoption separate. Preserve the existing Python
stdlib/SQLite coordinator and CLI boundaries. The user requested continued work
on all recorded gaps and separately authorized one session/two calls/five minutes
for a tool-free live resume acceptance.

## Approach and boundaries

Extend the existing owner adapters and operation commands. Replacing the runtime
or adding a distributed scheduler would not resolve missing PIT evidence and
would duplicate owner state. A write-enabled browser is deferred until operator
roles and mutation approval have a separate explicit contract; the installed GUI
continues read-only. The public Pages site remains synthetic.

Research owns a bounded, versioned handle-based tool gateway and optional MCP
transport; v1 Codex execution remains tool-free. Tool profiles pin configuration,
artifact identities and approved operations; callers cannot supply arbitrary
paths or shell commands. Any Codex opt-in profile must preserve deterministic
host enforcement. Research submission must retain existing approval checks.

Completed externally executed Codex turns can be attached as immutable evidence
through an observe action. Observe never starts, resumes or cancels a model; it
binds the exact receipt/session/turn and projects usage. This makes actual
acceptance evidence visible without spending another inference call.

Data normalization and PIT building use existing owner CLIs on retained inputs
under a new private task directory. Observation-time availability must remain
honest; recent retrieval cannot establish historical visibility. A real study
that lacks evidence stays blocked. End-to-end tests use installed owners and
isolated synthetic inputs, without claiming qualified economic results.

Recovery verifies checksums, SQLite integrity and schema before publishing a new
restore target. Notification attempts have durable identity and uncertain-send
reconciliation; only local peers are exercised. Migration preflight distinguishes
old/new scheduler ownership, refuses overlap, and never switches timers. No
external messages or production cutover are performed by acceptance tests.

## Acceptance

budget. Run all available installed-owner checks, deterministic end-to-end and
recovery faults, CLI tests, browser acceptance and independent review. Record

merged consumer release and verify the private read-only workbench. Preserve
