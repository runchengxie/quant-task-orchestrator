# Research workbench clarity

The user approved simplifying the existing GUI and Pages demo around progress, blockers and next actions. Keep the existing vanilla JavaScript, bilingual catalogs and read-only API.

## Approaches
Keep a technical dashboard; replace it with a graph-first application; or use an attention-first workflow list with a supplementary graph. The approved recommendation is the third: it supports daily inspection without making users interpret a graph first.

## Design
Show three summaries of loaded workflows: needs attention, in progress, completed execution. State the loaded scope explicitly. Preserve computation versus research qualification as separate facts. Put workflow identity hashes and permissions in technical details. Show recorded recovery guidance near the selected workflow summary. Keep evidence, event history and operating metrics available through progressive disclosure. Use a neutral canvas, restrained green accent, clear typography and responsive stacking. Preserve locale, memory-only tokens, authentication epochs, text escaping and GET-only behavior.

Pages uses synthetic examples only, with clear successful execution, evidence blocking and execution failure cases. No new backend, framework, model calls or production schedule changes.

## Acceptance
Desktop and mobile fit without horizontal page overflow; both languages remain usable; keyboard controls work; technical panels stay closed until requested and survive refresh; unknown evidence never becomes qualified; all existing security and browser checks pass.
