# quant-task-orchestrator

[简体中文](README.zh-CN.md) · [Interactive demo](https://runchengxie.github.io/quant-task-orchestrator/)

Coordinate quantitative research workflows across independent domain owners.
Track a task's dependencies, approval, assignments, recovery and evidence through
a CLI, terminal UI and local JSON API.

The coordinator owns the workflow. **Runtime owns execution; Research owns
admission, evidence and promotion.** A successful backtest never approves a strategy.

## Current scope

- SQLite workflows and DAG dependencies, explicit plan-hash approvals and audit events.
- Runtime CLI: plan-bound submission, original-key reconciliation, verified results and cancellation.
- Research CLI: reconciliation of an **existing approved campaign proposal**; no new
  proposal admission or conclusion is generated by this adapter.
- Bounded Codex CLI turns through the Research Owner: explicit start/resume/cancel and observed usage.
- Cross-repository Skill catalog and text installation pinned to exact Git commits and hashes.
- Live read-only local GUI, TUI and loopback JSON API with optional private bearer authentication.
- Data/report owner verification, raw observation byte verification, retained native-session inspection.
- Durable publication inbox, local notification outbox, staged releases and SQLite backups.
- Explicit evidence gates plus observed workflow durations, owner calls and operator actions.
- Responsive English/Chinese GitHub Pages demo using fictional data and simulated controls.

Python 3.12+ on Linux, no runtime dependencies. Single machine, one coordinator per
database. This is an initial coordination release, not a distributed scheduler.
Existing owners remain independently operable. Production schedules are unchanged.

## Start here

```sh
python -m pip install .
quant-task --help
quant-task --database "$TASK_DATABASE" tui --once
quant-task --database "$TASK_DATABASE" serve-api --port 8787
```

`TASK_DATABASE` must refer to an existing coordinator database for read operations.
See [setup and synthetic quickstart](docs/setup.md) to create one.
